HARDENING NOTES
1 · Slot lock enforced in Postgres too — unique (pitch_id, starts_at) with pending state; Redis TTL alone can race late webhooks · 2 · Installments: balance unpaid by play-day cutoff → auto-cancel + partial refund policy · 3 · PSP webhooks: idempotency key per charge + reconciliation cron polling stuck pendings · 4 · Repeat bookings: reserve all future slots, auto-release if unpaid 24h before session · 5 · Protected time: gate check-in scan timestamps feed dispute evidence
KEY FLOWS
Booking: lock slot (Redis) → charge (PSP webhook) → confirm → SMS/push · Split: ledger shares → QR session → auto-confirm when funded or organizer covers · Payout: weekly run = gross − fee − refunds → mobile money

KEY USER FLOWS
1 · Book & split
Search / Pitch AI→ Pick slots + duration→ Slot lock (Redis, 10 min)→ Extras + tips→ Split ×n → QR + WhatsApp links→ STK push / QR shares→ Confirmed · code + SMS
2 · Scan-to-pay (no app)
Scan QR→ pay.pitchtz.co.tz/s/:code (Pages + Turnstile)→ See share amount→ M-Pesa STK push→ Webhook → ledger update (BullMQ)→ SMS receipt · booking auto-confirms when funded
3 · Owner payout
Railway cron (Fri)→ Aggregate week: gross − 10% fee − refunds→ B2C mobile-money transfer→ Guards fund + tips distributed→ Statement in owner dashboard
